# English

## Architecture decision records

Decisions that shape TimeVault, with their alternatives and consequences. Each file is bilingual (English first, then Simplified Chinese). plan.md P0 asks for ADRs on snapshot semantics, the data model, the content object format and the service privilege boundary; the table says where each is covered. 0005 and 0006 were added for version 0.1.1, 0007 and 0008 for version 0.1.3, 0009, 0010 and 0011 for version 0.1.4, 0012 for version 0.1.5, 0013 for version 0.1.7, 0014 for version 0.1.8, 0015 for version 0.1.9, 0016 for version 1.0.0; 0009 was updated for version 0.1.6. 0005 says that TimeVault only reads Redis and 0009 that its Redis account is read-only on purpose; 0016 amends that for one list, the web log (the accounts and the single sign-on results are still only read, and the account still must not delete keys). 0017 and 0018 were added for version 1.0.1: the operating settings moved into the database, and a native NTFS index replaced Everything; they revise parts of 0003, 0004, 0006 and 0011, which carry a note about it. 0019 (several servers, one database, one schema each) was decided on 2026-11-22; its step 1, the read-only part, was built for version 1.1.0, and steps 2 and 3 are plans.

| ADR | Decision | Covers (plan.md P0) |
|---|---|---|
| [0001](./0001-recovery-point-history-model.md) | Recovery points and per-path validity ranges in PostgreSQL | Data model; what a recovery point means in the catalog |
| [0002](./0002-content-addressed-repository.md) | One content-addressed object per file in a separate repository folder | Content object format |
| [0003](./0003-live-scan-without-vss-and-usn.md) | Live scan instead of VSS and USN in the MVP (a deliberate deviation from plan.md; since 1.0.1 the index reads the journal and backups still do not, see 0018) | Snapshot semantics (provisional) |
| [0004](./0004-restore-safety-and-privileges.md) | Restore only below the restore root, with preview, token and confinement; single unprivileged process (since 1.0.1 the service runs elevated, see 0018) | Service privilege boundary; restore safety |
| [0005](./0005-redis-user-directory-and-open-browsing.md) | Anyone can browse; company accounts from the Redis user directory sign in to do anything else; roles `user` and `admin` (a deliberate exception to plan.md's "no Redis") | Role model (first version) |
| [0006](./0006-settings-in-env-and-database-and-scheduled-backups.md) | Deployment settings in `.env` or the environment (since 1.0.1 only the bootstrap settings and the secrets, see 0017), monitored folders in the database, automatic backups every N minutes that record nothing when nothing changed | Configuration; scheduling (first version) |
| [0007](./0007-display-folders-and-hiding-server-paths.md) | Monitored folders have a display folder (the network path people use); only administrators see the real folders of the server, and texts that quote them are rewritten for everybody else; `TIMEVAULT_SERVER_HOST` makes the display folder mandatory and checks its host | Role model (what each role sees) |
| [0008](./0008-folder-lists-are-cut-on-the-server.md) | Folder lists are filtered by type, sorted and cut into pages on the server by one engine, for the pages and the API alike | Browsing and search UX |
| [0009](./0009-single-sign-on-and-trusted-proxies.md) | Single sign-on through the company sign-on service: the result is read from Redis (never deleted) for a token this server issued, bound to the address of the browser; reverse proxies are named in `TIMEVAULT_TRUSTED_PROXIES`, also when two proxies are in a row (0.1.6) | Role model (sign-in); Windows SSO |
| [0010](./0010-version-limit-and-garbage-collection.md) | A limit of versions per file for each monitored folder: older versions roll off, the recovery points that lose versions are marked partial, and repository content nobody refers to is swept while no backup runs | Retention and garbage collection |
| [0011](./0011-staggered-scheduler-and-change-probe.md) | Automatic backups run one at a time with a gap and a rest, ordered by need; an index can tell that a folder did not change so that it is not scanned (Everything until 1.0.0, the NTFS index since 1.0.1, see 0018); the service runs at a lower priority | Scheduling (second version) |
| [0012](./0012-base-path-behind-a-reverse-proxy.md) | The site can be served under a path prefix such as `/tv` behind a reverse proxy: the prefix is taken off a request and put on the redirects, links, assets, script requests and cookies, and the proxy may keep or remove it | Web layer, deployment |
| [0013](./0013-per-folder-access-levels.md) | What an account may do is decided for each monitored folder: Browse, Back up (with the full re-read) and Full, granted to guests, to everybody who is signed in or to single employee IDs; a folder without a level is invisible; administrators have Full everywhere; new folders are seen by administrators only until they are given access | Role model (per-source permissions) |
| [0014](./0014-self-update-from-a-release-manifest.md) | The service updates itself from a release folder (`timevault.exe` and `timevault.json`, written by `scripts/release.ps1`): when `latest_version` is not the running version it downloads and checks the program, stops taking jobs, waits for the running ones, swaps the file by renaming it, and restarts through a small launcher (or exit code 75); no signature, no automatic way back | Deployment, continuous delivery |
| [0015](./0015-account-pictures-are-read-by-the-browser-from-their-host.md) | The browser reads the pictures of the accounts from the host that keeps them (by default `http://<TIMEVAULT_SERVER_HOST>/api/static/hr/{id}.webp`): an image element decides what is a picture (the host sends `text/plain` and answers a missing one with `202` and a 480×320 placeholder), the content security policy lists that host for images only (the wildcard of the domain for a host name with an underscore), and the service fetches and serves nothing; the update address stays an explicit setting | Web layer, deployment |
| [0016](./0016-web-log-in-the-shared-redis-list.md) | The service appends a web log to the Redis list `web_log` that the company's applications share, in the encoding and the six-field line they use (`zlib` of a `pickle`): page views, failed requests, every audit event and what the scheduler does, with the account as `user=<employee ID>` in the message; on by default when Redis is configured (`TIMEVAULT_WEB_LOG`); best effort, with a queue, limits and a back-off; never trimmed by TimeVault; nothing typed, no path and no error text is written; the key may not lie in the namespace of the accounts or of the sign-on results; `internal/redisuser` stays read-only. Amends the "only reads Redis" of 0005 and the read-only Redis account of 0009 | Logging, deployment (Redis) |
| [0017](./0017-site-settings-in-the-database.md) | The operating settings are Site settings in the database (26 settings in seven groups), read and changed only by the local administrator on the Site settings page, in the API and with `timevault-server settings`; they take effect after a restart (a button does it); only the bootstrap settings and the secrets stay in `.env`; nothing is carried over from an old `.env`; changes are audited by key name, never value. Replaces the settings part of 0006 | Configuration; role model (the local administrator) |
| [0018](./0018-native-ntfs-index-replaces-everything.md) | A native NTFS index replaces Everything: the service builds an in-memory index of the monitored folders from the file records of the volume and keeps it current from the change journal, for search, folder sizes and the scheduler's change probe; the whole service runs with administrator rights; core features only; nothing to install or switch on. Revises 0003, 0004 and 0011 | Search; service privilege boundary; change detection |
| [0019](./0019-several-servers-one-database-one-schema-each.md) | Several servers share one database, one schema each, so that people see and search all of them from one address: each server keeps its own repository, and no file content crosses servers; the person works in the pages of the server they are signed in to, which reads the history from the database and asks the owning server, through a signed server-to-server API, for the live view, the search and every action (no jump to the other server); a registry of servers, a read contract, permissions as now, no shared session key; the first server can be moved into a schema of its own by one explicit command. **Step 1 (read-only) built in 1.1.0; steps 2 and 3 planned** | Role model, deployment, search |

Not decided yet, because the spikes were not run: VSS usage, chunking and packs (the index has read the USN journal since 1.0.1, see 0018; backups do not use it).

# 中文

## 架构决策记录

塑造 TimeVault 的各项决定，包括备选方案和影响。每个文件都是双语的（先英文，后简体中文）。plan.md P0 要求为快照语义、数据模型、内容对象格式和服务权限边界编写 ADR；下表说明各项分别在哪里覆盖。0005 和 0006 是为 0.1.1 版本新增的，0007 和 0008 是为 0.1.3 版本新增的，0009、0010 和 0011 是为 0.1.4 版本新增的，0012 是为 0.1.5 版本新增的，0013 是为 0.1.7 版本新增的，0014 是为 0.1.8 版本新增的，0015 是为 0.1.9 版本新增的，0016 是为 1.0.0 版本新增的；0009 在 0.1.6 版本中有更新。0005 说 TimeVault 只读取 Redis，0009 说它的 Redis 账号有意设为只读；0016 对其中的一个列表，即 Web 日志，修订了这一点（账号和单点登录结果仍然只读取，该账号仍然不能删除键）。0017 和 0018 是为 1.0.1 版本新增的：运行设置移入了数据库，原生 NTFS 索引取代了 Everything；它们修订了 0003、0004、0006 和 0011 的一部分，这些记录里带有相应的说明。0019（几台服务器共用一个数据库、各用一个 schema）于 2026-11-22 决定；它的第 1 步，即只读的部分，已为 1.1.0 版建成，第 2、3 步是计划。

| ADR | 决定 | 覆盖的内容（plan.md P0） |
|---|---|---|
| [0001](./0001-recovery-point-history-model.md) | 在 PostgreSQL 中使用恢复点和按路径的有效区间 | 数据模型；恢复点在目录库中的含义 |
| [0002](./0002-content-addressed-repository.md) | 在独立的仓库文件夹中，每个文件对应一个内容寻址对象 | 内容对象格式 |
| [0003](./0003-live-scan-without-vss-and-usn.md) | MVP 采用实时扫描，而不是 VSS 和 USN（有意偏离 plan.md；自 1.0.1 起索引会读取 journal，而备份仍然不读，见 0018） | 快照语义（暂定） |
| [0004](./0004-restore-safety-and-privileges.md) | 只恢复到恢复根目录之下，需要预览、令牌和约束；单个非特权进程（自 1.0.1 起服务以提升的权限运行，见 0018） | 服务权限边界；恢复安全 |
| [0005](./0005-redis-user-directory-and-open-browsing.md) | 任何人都可以浏览；其他操作需要用 Redis 用户目录中的公司账号登录；角色为 `user` 和 `admin`（有意偏离 plan.md 的"不引入 Redis"） | 角色模型（第一版） |
| [0006](./0006-settings-in-env-and-database-and-scheduled-backups.md) | 部署设置放在 `.env` 或环境变量中（自 1.0.1 起只有引导设置和机密，见 0017），监控文件夹放在数据库中，每 N 分钟自动备份，没有变化时不记录任何内容 | 配置；计划任务（第一版） |
| [0007](./0007-display-folders-and-hiding-server-paths.md) | 监控文件夹有显示文件夹（人们使用的网络路径）；只有管理员能看到服务器上的真实文件夹，引用它们的文本会为其他人改写；`TIMEVAULT_SERVER_HOST` 让显示文件夹成为必填并检查它的主机 | 角色模型（各角色能看到什么） |
| [0008](./0008-folder-lists-are-cut-on-the-server.md) | 文件夹列表由一个引擎在服务器上按类型筛选、排序并切分成页，页面和 API 一致 | 浏览与搜索体验 |
| [0009](./0009-single-sign-on-and-trusted-proxies.md) | 通过公司单点登录服务实现单点登录：对本服务器签发的令牌，从 Redis 读取结果（从不删除），并与浏览器的地址绑定；反向代理在 `TIMEVAULT_TRUSTED_PROXIES` 中指明，两层代理时也是如此（0.1.6） | 角色模型（登录）；Windows SSO |
| [0010](./0010-version-limit-and-garbage-collection.md) | 每个监控文件夹设置每个文件的版本数上限：较旧的版本滚动删除，失去版本的恢复点被标记为不完整，没有备份运行时清扫无人引用的仓库内容 | 保留策略与垃圾回收 |
| [0011](./0011-staggered-scheduler-and-change-probe.md) | 自动备份一次运行一个，带间隔和休息，并按需要排序；索引可以告知某个文件夹没有变化从而不扫描它（1.0.0 及之前是 Everything，自 1.0.1 起是 NTFS 索引，见 0018）；服务以较低优先级运行 | 计划任务（第二版） |
| [0012](./0012-base-path-behind-a-reverse-proxy.md) | 站点可以放在反向代理之后的路径前缀（如 `/tv`）下提供：请求上的前缀会被去掉，重定向、链接、静态资源、脚本请求和 Cookie 会加上前缀，代理可以保留也可以去掉它 | Web 层、部署 |
| [0013](./0013-per-folder-access-levels.md) | 账号能做什么按监控文件夹分别决定：浏览、备份（含完整重读）和完全，可以授予访客、所有已登录的人或单个工号；没有任何级别的文件夹是不可见的；管理员对所有文件夹拥有完全控制权；新文件夹在被授予访问权之前只有管理员能看到 | 角色模型（按备份源的权限） |
| [0014](./0014-self-update-from-a-release-manifest.md) | 服务从发布文件夹（由 `scripts/release.ps1` 生成的 `timevault.exe` 和 `timevault.json`）更新自己：当 `latest_version` 不是正在运行的版本时，下载并检查程序，停止取用任务，等正在运行的任务结束，通过重命名交换文件，再通过一个小型启动器（或退出码 75）重启；没有签名，没有自动回退 | 部署、持续交付 |
| [0015](./0015-account-pictures-are-read-by-the-browser-from-their-host.md) | 由浏览器从存放头像的主机读取账号头像（默认 `http://<TIMEVAULT_SERVER_HOST>/api/static/hr/{id}.webp`）：由图片元素决定什么是头像（该主机以 `text/plain` 发送，对缺失的头像回答 `202` 和一张 480×320 的占位图），内容安全策略只为图片列出该主机（主机名带下划线时用其所在域的通配符），服务不获取也不提供任何东西；更新地址仍然是显式设置 | Web 层、部署 |
| [0016](./0016-web-log-in-the-shared-redis-list.md) | 服务把 Web 日志追加到公司各应用共用的 Redis 列表 `web_log`，使用它们所用的编码和六个字段的行（`pickle` 之后再 `zlib`）：页面访问、失败的请求、每一个审计事件和调度器所做的事，账号以 `user=<工号>` 写在 message 中；配置了 Redis 时默认开启（`TIMEVAULT_WEB_LOG`）；尽力而为，带队列、限制和退避；TimeVault 从不裁剪它；不写入任何输入的内容、路径和错误文本；键不能位于账号或单点登录结果的命名空间之内；`internal/redisuser` 仍然只读。修订了 0005 中"只读取 Redis"的说法和 0009 中只读的 Redis 账号 | 日志、部署（Redis） |
| [0017](./0017-site-settings-in-the-database.md) | 运行设置是保存在数据库中的站点设置（分七组共 26 个设置），只有本地管理员能在站点设置页、API 和 `timevault-server settings` 中读取和修改；它们在重启之后生效（有按钮可以重启）；只有引导设置和机密仍留在 `.env` 中；不会从旧的 `.env` 带过来任何东西；修改按键名记入审计，绝不记录值。取代 0006 中关于设置的部分 | 配置；角色模型（本地管理员） |
| [0018](./0018-native-ntfs-index-replaces-everything.md) | 原生 NTFS 索引取代 Everything：服务由卷的文件记录建立监控文件夹的内存索引，并由变更日志保持最新，用于搜索、文件夹大小和调度器的变更探测；整个服务以管理员权限运行；只做核心功能；不需要安装或打开任何东西。修订了 0003、0004 和 0011 | 搜索；服务权限边界；变更检测 |
| [0019](./0019-several-servers-one-database-one-schema-each.md) | 几台服务器共用一个数据库、各用一个 schema，让人们从一个地址就能看到并搜索所有服务器：每台服务器保留自己的仓库，文件内容不在服务器之间传输；人在自己登录的那台服务器的页面里工作，它从数据库读取历史，并通过带签名的服务器间 API 请文件夹所属的服务器提供实时视图、搜索和执行每个操作（不跳转到另一台服务器）；有服务器登记表和读取契约，权限与现在一样，不共用会话密钥；第一台服务器可以用一个明确的命令搬进它自己的 schema。**第 1 步（只读）已在 1.1.0 中建成；第 2、3 步为计划** | 角色模型、部署、搜索 |

尚未决定的内容（因为没有做验证）：VSS 的使用、分块与 Pack（自 1.0.1 起索引已经在读取 USN journal，见 0018；备份不使用它）。
