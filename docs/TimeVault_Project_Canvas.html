Project definition / 项目定义

TimeVault Project Canvas

A one-page product charter for an internal, self-hosted Windows Server file time machine.用于企业内部 Windows Server 文件时间机器的一页式项目启动画布。

01

Problem 要解决的问题

Ordinary file shares do not provide convenient multi-version discovery and safe recovery at chosen historical points.共享文件难以快速追溯旧版、已删文件和历史目录，并安全恢复。

02

Users 目标用户

File server admins, IT operators, and authorized file owners. Start with a controlled pilot group.文件服务器管理员、IT 运维与获授权的文件所有人；先小范围试点。

03

Value 核心价值

Everything-speed discovery plus Time Machine-style history browsing, with controlled recoverability.Everything 级搜索速度 + Time Machine 式时间轴 + 可验证、安全的恢复。

04

Core scenarios 典型场景

  • Recover a deleted file / 恢复误删文件
  • Roll back a document / 找回旧版文档
  • Restore a folder at T / 恢复指定时间的目录
05

Key features 主要功能

  • Current search and explorer / 搜索与目录树
  • Timeline + versions / 时间轴和版本
  • Jobs, retention, restore / 任务、保留和恢复
06

Guardrails 安全边界

  • Real recovery points only / 不虚构恢复点
  • Read ACLs + audit / 权限与审计
  • Preview before overwrite / 覆盖前预览
07

Technical choices 技术选择

Go web app, Everything local API, PostgreSQL history, NTFS USN, Windows VSS, independent immutable object repository.Go、Everything、PostgreSQL、USN、VSS 与独立不可变备份仓库。

08

Success signals 验收指标

5M-file pilot, bounded search performance, verified restores, restart safety, reproducible recovery drills.通过 500 万文件试验、恢复校验、故障恢复和可重复恢复演练。

09

Non-goals / 暂不实现

Bare-metal OS recovery, per-second continuous protection, universal app-aware DB backup, multi-site storage replication.不包含裸机恢复、秒级连续保护、通用数据库备份及多站点复制。

Open decisions before implementation / 开发前需要确认

Source scope / 备份范围Which server volumes and folders? Local NTFS vs SMB paths? / 哪些服务器卷和目录？
Capacity / 数据容量Total bytes, changed bytes/day, target backup repository and throughput. / 总容量、日变化量、仓库与吞吐。
Policy / 备份策略Recovery point interval, retention, RPO/RTO, off-host copy requirements. / 时间间隔、保留期限、恢复目标与异地副本。
Permissions / 访问权限AD/Windows SSO model, NTFS ACL visibility, restore and overwrite approvals. / AD 认证、NTFS ACL、恢复审批。
System design / 系统设计

Architecture at a glance

Everything accelerates current search. USN detects change candidates. VSS offers consistent source views. TimeVault commits durable history to an independent repository.Everything 提供当前搜索，USN 定位变更，VSS 提供一致性读取，TimeVault 保存独立历史副本。

Go Web UI

Explorer, timeline, restore preview, jobs, SSO.目录、时间轴、预览、任务和登录。

Everything

Current-file index and bounded search.现有文件索引与分页查询。

VSS + USN

Consistent snapshots and change candidates.一致性快照与变更检测。

PostgreSQL

Versioned catalog, recovery points, audit.历史元数据、恢复点与审计。

Backup Vault

Verified immutable objects on separate storage.独立存储、去重和校验。

Rule 01 — Recovery points are real / 恢复点必须真实

The UI can only offer committed, verifiable backups. A continuous date picker cannot create data that was never saved.只允许选择已提交、可校验的备份；时间选择器不会凭空产生未备份的数据。

Rule 02 — Safe by default / 默认安全

Restore to an alternate folder, show conflicts and require explicit confirmation before overwriting source files.默认恢复到其他目录，先预览冲突，覆盖线上文件前必须再次确认。

Rule 03 — No leakage / 不泄露权限

Everything's global index must not bypass NTFS ACLs or application authorization. Only the Go service can query its local API.Everything 全局索引不等于用户可访问范围，必须由 Go 服务完成授权校验。

Rule 04 — Independent storage / 独立备份仓库

Content and metadata are separately protected, regularly verified, and recoverable without the original source disk.备份内容与元数据应独立保护、定期校验，源磁盘损坏后仍可恢复。

Delivery plan / 开发计划

Build in verified phases

Do not skip the Windows-specific proof of concept or the security review. Each phase has a clear completion gate.必须先完成 Windows 底层能力验证，再逐步实施与验收，避免直接操作生产数据。

P0

Technical spike 技术验证

Everything API, VSS creation/cleanup, USN continuity, 5M scale benchmarks; confirm volume/storage assumptions.验证 Everything、VSS、USN、规模性能及备份范围。

P1

Read-only explorer 只读文件浏览器

Go web shell, secure search, directory tree, pagination, SSO and health monitoring.Go 页面、安全搜索、目录树、分页、身份验证和健康状态。

P2

Backup and history 备份与版本记录

Initial/incremental backups, immutable objects, manifest commit, historical browser and retention.全量与增量备份、历史 Manifest、版本记录及保留策略。

P3

Safe restore 安全恢复

Dry-run diff, alternate-target restore, authorized in-place restore, verification and audit.恢复预览、异地恢复、确认后覆盖、校验与审计。

P4

Production hardening 生产稳定化

Fault injection, retention GC, repository integrity checks, 5M load tests and off-host recovery drill.故障演练、清理、完整性校验、压力测试及异机恢复。

First action / 首个任务: inventory source volumes and total bytes, establish an isolated Windows Server test volume, then begin P0. All detailed tasks and acceptance criteria are in plan.md.先确认源卷、总容量和隔离测试环境，然后启动 P0。详细任务及验收条件请查阅 plan.md。
