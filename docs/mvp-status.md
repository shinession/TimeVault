# English

## Overview

This is the honest status of TimeVault against [plan.md](./plan.md). It is a **vertical slice**: one working path through search/browse, backup, history and restore on a local NTFS folder. It is not a production backup system, and nothing here has been run at the 5-million-file scale. Version 0.1.1 added open browsing, company sign-in with two roles, a Settings page for the monitored folders and automatic backups; version 0.1.3 added sorted, filtered and paged folder lists with a Type column, display folders for the monitored folders, and the rule that only administrators see the server's real folders; version 0.1.4 added single sign-on, folder sizes from Everything, the duration of every operation in the audit log, a limit of versions per file with rolling deletion, and automatic backups that are spread out; version 0.1.5 lets the site be served under a path prefix such as `/tv` behind a reverse proxy; version 0.1.6 makes a single sign-on that is refused over the addresses say why, and documents two proxies in a row; version 0.1.7 decides what an account may do for each monitored folder (Browse, Back up, Full control) and hides the folders that a visitor may not browse; version 0.1.8 shows the pictures of the accounts and lets the service update itself from a release folder that `scripts\release.ps1` writes; version 0.1.9 makes the pictures show (the browser reads them from the host in `server_host`, which the other application sends as `text/plain`) and says where the release is published on that host; version 0.1.10 changes only the version number, so that the automatic update can be tried from one release to the next; version 1.0.0, the first official release, makes the console log name the user and the address of every request, writes a web log to the Redis list that the company's other applications share (the first write that TimeVault makes to Redis), and gives every page except the sign-in page a **Documentation** button (the user guide at `/help`) and a **Guide** button (a step-by-step tour of the page); version 1.0.1 replaces Everything with an index of the monitored folders that the service builds itself from the NTFS volume and keeps current from its change journal (search, folder sizes and skipping the scan of a folder that did not change; it needs administrator rights), and moves the operating settings from `.env` into the database, where only the local administrator edits them on a Site settings page. The statements below are updated for them, and [changelog.md](./changelog.md) lists what changed.

Status words: **Done** (implemented and tested), **Partial** (works with stated limits), **Not done** (planned, not implemented), **Not verified** (no evidence yet).

## Known limitations

- Every backup that is not skipped walks the whole source: backups do not use the change journal (the index uses it to skip the scan of a folder that did not change, and for search), so a very large source is slow to back up.
- A rename or move of a large folder is recorded as delete plus add of every entry (the content bytes are stored once).
- Files are read from the live disk, not from a VSS snapshot ("Live scan" is shown on every point).
- Two roles (`user`, `admin`) and, for each monitored folder, three levels (Browse, Back up, Full control); no rights for a path inside a folder, and NTFS permissions are not consulted; no TLS inside the service. Anonymous visitors can see names, sizes and history of the folders that give guests Browse (see [security.md](./security.md)).
- No off-host copy, repository encryption or Windows service wrapper. Without a limit of versions per file, automatic backups only add recovery points; with one, the deleted versions are gone for good and the recovery points that lost them are partial.
- Chunking and pack files are not implemented: every file is one object, so millions of tiny files mean millions of repository files.
- The job log keeps at most 2,000 lines per job, and a restore stores per-item results for at most 20,000 successful items (failures are always stored).
- Sources must be local folders; network shares (UNC paths) are rejected as the folder to read (the display folder is only text people are shown, and is not read). A restore can select at most 500 paths and plan at most 2,000,000 items.
- Every page of a folder list reads the whole folder, so a folder with hundreds of thousands of entries takes seconds to open. The deleted-items panel shows at most 500 items, on the first page only.
- The display folder of a monitored folder is checked for its host, not for whether the share really leads to the folder; hiding the real folders in text works on decoded text and misses unusual spellings (see [security.md](./security.md)).
- A normal backup does not re-check that the repository still holds the content of files it carries over unchanged. An integrity check finds missing or damaged objects, and a **Full re-read** backup writes missing content again.
- If the service is killed in the instant between a backup's commit and the update of its job, the job is reported as failed ("interrupted by a service restart") although the recovery point was committed and is fine.
- Power-loss durability of the repository is best effort and untested (see [security.md](./security.md)).
- Only one service can run against a database; a second one refuses to start.
- A service that updates itself trusts whoever can write its release folder (no signature), has no automatic way back, waits for running jobs without a limit, and in `supervise` mode keeps a launcher that is not replaced by an update (see [security.md](./security.md) and [ADR 0014](./adr/0014-self-update-from-a-release-manifest.md)). The pictures of the accounts are another application's files, read by the browser from the host that keeps them (by default `server_host`, over plain `http`; see [ADR 0015](./adr/0015-account-pictures-are-read-by-the-browser-from-their-host.md)).
- The web log is best effort: lines are dropped when the queue is full, over the limits or while Redis does not answer, and a dropped line is not written later. It does not replace the audit trail, TimeVault never trims the shared list that it writes to, and the lines hold employee IDs and client addresses (see [security.md](./security.md) and [ADR 0016](./adr/0016-web-log-in-the-shared-redis-list.md)). The texts of the user guide and of the page guide exist in English and Chinese only.
- Search, folder sizes and the skipping of scans need the service to run with administrator rights, and only monitored folders on a local NTFS drive letter are indexed (not shares; ReFS, FAT and exFAT were not tried). The index takes about 230 bytes of memory for each entry of the monitored folders, and building it takes seconds (13 seconds for 2.0 million entries); a restart or a new build costs one more scan of each folder before skipping resumes. The whole service runs elevated for it (see [security.md](./security.md)). Every Site setting takes effect after a restart, and the values that 1.0.0 kept in `.env` are not carried over.

## Verification performed

This is what was actually run. Everything ran on one Windows machine against a private PostgreSQL 16 instance.

- **Automated checks.** `gofmt`, `go build ./...`, `go vet ./...` and `go test ./...` pass. The tests that need PostgreSQL each use a private schema. The fixes made after the two independent code reviews have regression tests; undoing a fix temporarily made its test fail.
- **End-to-end run of the real program (79 checks).** Sign-in, CSRF and security headers; source rules, including a junction that points into the repository; backups and history; byte-for-byte restores with modification times; conflict policies; tampered and hostile paths; deep verification detecting and clearing corruption; cancelling a running backup; the audit trail; the sign-in throttle.
- **Crash recovery (26 checks).** The service was killed in the middle of a backup of 6,000 files. After the restart the partial rows were gone, the job was marked failed, no partial recovery point was visible, the next backup recorded all 6,000 files, and a second instance refused to start without disturbing a running job.
- **Search (0.1.x).** The Everything adapter was exercised against a real Everything 1.4.1.1024 instance in an isolated configuration; it was removed in 1.0.1 (see Version 1.0.1).
- **Browser check** (light and dark theme, English and Chinese). Sign-in and sign-out; Explorer, Time Machine, Backups, Status and the restore preview; a restore started from the form and compared with the source (450 files, identical names, content and modification times); **Load more** and **Select all** on a folder of 450 entries; and the job page during a backup of 20,000 files (about 15 seconds), where the counters, phase and state update on their own.

# 中文

## 概述

这是 TimeVault 相对于 [plan.md](./plan.md) 的真实状态。它是一个**垂直切片**：在本地 NTFS 文件夹上，打通"搜索/浏览、备份、历史、恢复"这一条完整路径。它不是生产级备份系统，这里的任何内容都没有在 500 万文件规模上运行过。0.1.1 版增加了开放浏览、带两种角色的公司账号登录、管理监控文件夹的设置页和自动备份；0.1.3 版增加了可排序、可筛选、可分页的文件夹列表（带类型列）、监控文件夹的显示文件夹，以及只有管理员才能看到服务器真实文件夹的规则；0.1.4 版增加了单点登录、来自 Everything 的文件夹大小、审计日志中每个操作的耗时、每个文件的版本数上限及滚动删除，以及错开时间的自动备份；0.1.5 版让站点可以放在反向代理之后的 `/tv` 等路径前缀下提供服务；0.1.6 版让因地址而被拒绝的单点登录说明原因，并说明了两层代理的配置；0.1.7 版按每个监控文件夹分别决定账号能做什么（浏览、备份、完全控制），并隐藏访问者无权浏览的文件夹；0.1.8 版显示账号头像，并让服务从 `scripts\release.ps1` 生成的发布文件夹更新自己；0.1.9 版让头像真正显示出来（由浏览器从 `server_host` 所指的主机读取，另一个应用把头像以 `text/plain` 发送），并说明了发布放在那台主机的哪里；0.1.10 版只改了版本号，用来试一试从一个发布自动更新到下一个发布；1.0.0 版是第一个正式版本，让控制台日志写出每个请求的用户和地址，把 Web 日志写入公司其他应用共用的 Redis 列表（TimeVault 对 Redis 的第一次写入），并让除登录页之外的每个页面都有**文档**按钮（`/help` 的用户手册）和**页面导览**按钮（逐步介绍本页）；1.0.1 版用服务自己由 NTFS 卷建立、并由卷的变更日志保持最新的监控文件夹索引取代 Everything（搜索、文件夹大小和跳过未变化文件夹的扫描；需要管理员权限），并把运行设置从 `.env` 移入数据库，由只有本地管理员能操作的站点设置页编辑。下文的表述已按它们更新，[changelog.md](./changelog.md) 列出了具体改动。

状态用语：**已完成**（已实现且有测试）、**部分完成**（可用但有所述限制）、**未完成**（有计划但未实现）、**未验证**（暂无证据）。

## 已知限制

- 每次没有被跳过的备份都会遍历整个备份源：备份不使用变更日志（索引用它来跳过没有变化的文件夹的扫描，并用于搜索），所以非常大的备份源备份起来会比较慢。
- 大文件夹的重命名或移动会被记录为每一项的"删除 + 新增"（内容字节只存一份）。
- 文件读取自在线磁盘，而不是 VSS 快照（每个恢复点都会显示"实时扫描"）。
- 两种角色（`user`、`admin`），以及每个监控文件夹上的三个级别（浏览、备份、完全控制）；没有针对文件夹内某个路径的权限，也不会查询 NTFS 权限；服务内没有 TLS。匿名访问者可以看到允许访客浏览的文件夹的名称、大小和历史（见 [security.md](./security.md)）。
- 没有异机副本、仓库加密或 Windows 服务封装。没有每个文件的版本数上限时，自动备份只会不断增加恢复点；有上限时，被删除的版本永远消失，失去它们的恢复点是不完整的。
- 没有实现分块和 Pack 文件：每个文件就是一个对象，所以数百万个小文件意味着仓库中有数百万个文件。
- 每个任务的日志最多保留 2,000 行；恢复最多存储 20,000 个成功项目的逐项结果（失败项始终存储）。
- 备份源必须是本地文件夹；网络共享（UNC 路径）作为要读取的文件夹会被拒绝（显示文件夹只是展示给人们看的文本，不会被读取）。一次恢复最多可选择 500 个路径，最多规划 2,000,000 个条目。
- 文件夹列表的每一页都会读取整个文件夹，所以包含几十万个条目的文件夹需要几秒钟才能打开。已删除项目面板最多显示 500 项，并且只在第一页显示。
- 监控文件夹的显示文件夹只检查主机，不检查共享是否真的通向该文件夹；在文本中隐藏真实文件夹是基于已解码文本的，会漏掉不寻常的写法（见 [security.md](./security.md)）。
- 普通备份不会重新检查仓库中是否仍然保存着它原样沿用的未变化文件的内容。完整性校验可以发现缺失或损坏的对象，而**完整重读**备份会把缺失的内容重新写入。
- 如果服务恰好在备份提交与其任务更新之间的瞬间被强制终止，任务会被报告为失败（"interrupted by a service restart"），尽管恢复点已经提交并且完好。
- 仓库在断电后的持久性是尽力而为，且未经测试（见 [security.md](./security.md)）。
- 同一个数据库只能运行一个服务；第二个服务会拒绝启动。
- 会自己更新的服务信任任何能写入它的发布文件夹的人（没有签名），没有自动回退，会无限期地等待正在运行的任务，并且在 `supervise` 模式下会保留一个不会随更新被替换的启动器（见 [security.md](./security.md) 和 [ADR 0014](./adr/0014-self-update-from-a-release-manifest.md)）。账号头像是另一个应用的文件，由浏览器从存放它们的主机读取（默认是 `server_host`，使用明文 `http`；见 [ADR 0015](./adr/0015-account-pictures-are-read-by-the-browser-from-their-host.md)）。
- Web 日志是尽力而为的：队列已满、超出限制或 Redis 不应答时会丢弃行，被丢弃的行以后不会再写。它不能替代审计记录，TimeVault 从不裁剪它所写入的共用列表，而且这些行里有工号和客户端地址（见 [security.md](./security.md) 和 [ADR 0016](./adr/0016-web-log-in-the-shared-redis-list.md)）。用户手册和页面导览的文字只有英文和中文两种。
- 搜索、文件夹大小和跳过扫描要求服务以管理员权限运行，并且只有位于本地 NTFS 盘符上的监控文件夹会被建立索引（网络共享不会；没有试过 ReFS、FAT 和 exFAT）。索引为监控文件夹的每个条目大约占用 230 字节内存，建立它需要几秒钟（200 万个条目需要 13 秒）；重启或重新建立之后，每个文件夹要多扫描一次才会恢复跳过。为此整个服务都在提升权限下运行（见 [security.md](./security.md)）。每个站点设置都在重启之后才生效，而 1.0.0 保存在 `.env` 里的值不会被带过来。

## 已执行的验证

以下是实际运行过的验证。所有验证都在一台 Windows 机器上、针对一个私有的 PostgreSQL 16 实例进行。

- **自动化检查。** `gofmt`、`go build ./...`、`go vet ./...` 和 `go test ./...` 均通过。需要 PostgreSQL 的测试各自使用一个私有 schema。两轮独立代码审查之后做的修复都有回归测试；临时撤销某项修复后，对应的测试会失败。
- **对真实程序的端到端运行（79 项检查）。** 登录、CSRF 与安全响应头；备份源规则（包括指向仓库的联接点）；备份与历史；逐字节一致且保留修改时间的恢复；冲突策略；被篡改的和恶意构造的路径；深度校验发现并清除损坏；取消运行中的备份；审计记录；登录限流。
- **崩溃恢复（26 项检查）。** 在备份 6,000 个文件的过程中强制终止服务。重启后，未完成的记录被清除，任务被标记为失败，没有任何不完整的恢复点可见，下一次备份记录了全部 6,000 个文件，并且第二个实例拒绝启动，不影响正在运行的任务。
- **搜索（0.1.x）。** Everything 适配器已针对真实的 Everything 1.4.1.1024 实例（隔离配置）运行过；它在 1.0.1 中被移除（见 1.0.1 版）。
- **浏览器检查**（浅色和深色主题，英文和中文）。登录与退出；文件浏览、时间机器、备份、状态和恢复预览页面；通过表单发起的恢复，并与源文件对比（450 个文件，名称、内容和修改时间完全一致）；在包含 450 项的文件夹上使用**加载更多**和**全选**；以及备份 20,000 个文件（约 15 秒）期间的任务页面，其计数器、阶段和状态会自动更新。

端到端运行和崩溃恢复运行所用的脚本是临时的，**不在**仓库中，所以无法用仓库重复这两次运行。

未验证：Windows Server 2019、Everything 1.5、恢复长度超过 260 字符的路径、500 万文件规模、断电持久性，以及在浏览器中点击**取消任务**按钮（取消功能本身已通过 HTTP 接口验证）。第二轮代码审查中关于恢复、登录和 HTTP 的、未修复的发现列在 [security.md](./security.md) 中。
